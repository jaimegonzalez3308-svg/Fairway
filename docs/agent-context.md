## Product and architecture

Fairway connects adult golfers in León: discover players and clubs, organize games, chat, record scores, and share photo stories. Keep its golf identity and existing characteristics. The website and installed iPhone app use one Next.js/React codebase and the same Supabase accounts, data, Storage, and permissions. Do not maintain a separate copy of the product for iOS.

The website's visual experience must stay the same when making app-only improvements. Native presentation is activated by Capacitor's iOS platform, `lib/use-native-app.ts`, and the `native-ios` CSS class, not screen width or user agent. Native styles belong in `app/native-app.css`. Safari remains the website.

Stack: Next.js 16, React 19, TypeScript, pnpm 10.28.2, Supabase, Capacitor 8, iOS Swift/Swift Package Manager, and Xcode. Follow the Next.js documentation rule in AGENTS.md. `package.json` is the authority for commands and dependencies.

## User requirements

- Preserve all existing edits and untracked work. Never reset, clean, stash, overwrite unrelated files, or commit unless requested.
- Make the installed app feel quicker and easier to use while retaining Fairway's identity and leaving the website layout intact.
- Use bottom tabs, reachable persistent Back controls, 44-point touch targets, safe areas, accessible spacing, and no hover-only controls. Remove native marketing clutter and large website footers.
- Support appropriate swipe-back, pull-to-refresh, and list swipe actions, with explicit accessible button equivalents. Respect VoiceOver and reduced motion.
- Open into useful app content; use a short 2–4-screen onboarding flow, deliberate loading/empty states, and friendly offline behavior.
- Keep secure persistent sessions, optional biometrics, Apple sign-in alongside Google, and in-app account deletion. Google's iOS login should use a system authentication sheet and return to the app.
- Camera capture and photo-library selection for stories should happen from the app with preview before publishing, using the same story backend as the website.
- Request permissions when needed. Provide push with a value explanation, deep/universal links, native sharing, haptics, badges, and widgets where useful. Avoid unnecessary contacts access.
- Cache key data and queue suitable actions safely. Do not imply every feature works offline or silently queue public/consent-sensitive actions.
- Reduce initial JavaScript and image weight, lazy-load heavy screens, and validate performance on real devices and slow networks before claiming measured startup or frame rates.
- Check current store payment rules before adding purchases. There is currently no active checkout or subscription catalog; do not invent a paywall or payment flow.

## Current implementation and limits

Capacitor's project is `ios/App/App.xcodeproj`, bundle ID `com.fairway.app`, with static web assets generated into `out/` and synced into `ios/App/App/public`. `pnpm ios:sync` rebuilds/copies the app; `pnpm ios:open` opens Xcode. Xcode edits do not publish the website or automatically update installed apps.

The app includes five bottom tabs (Descubrir · Partidas · Amigos · Mensajes · Mi perfil; on 2026-11-03 the user chose Amigos over Scores so friends are one tap away. Scores stays reachable via the Descubrir "Anotar score" quick action, the menu's "Mis scores" and Mi perfil), native panels/back controls, three onboarding steps, refresh/swipe controls, accessibility adjustments, camera stories, and native Google PKCE authentication. Sessions use Keychain with optional device biometric/passcode protection. An account-scoped private cache expires after 24 hours; up to 20 new private score drafts can queue and retry with stable UUIDs. Chats, public posts, and existing-score edits are not queued. A private-data-free Scores/Partidas widget is included.

Apple sign-in, Apple account deletion/revocation, push/APNs/outbox, badges, and universal-link routing/configuration have local implementations. The migration and Edge Functions are prepared, not deployed. The user has confirmed they do not have an Apple Developer Program membership/Team ID. Keep those services inactive; never configure an invented team or ask for an Apple password. Enabling them also requires real signing, backend configuration/secrets, and domain association.
